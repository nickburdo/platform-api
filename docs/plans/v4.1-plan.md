# Version 4.1 — Implementation Plan (Privacy Policy page)

> Status: **Approved** (2026-11-07) by the user in conversation.
> Depends on: Version 4 (`v4-plan.md`, Complete 2026-11-07)

## Goal

Serve a real public privacy policy at `GET /privacy`, so the Google OAuth consent screen's "Application privacy policy link" (Google Auth Platform → Branding) no longer points at `/docs`.

## Decisions

1. **Static HTML from the Worker**, a new `src/routes/privacy.routes.ts` mounted next to `docsRoutes`; no auth, no DB access.
2. **Not part of the OpenAPI document** — like `/docs` and `/openapi.json`, it is a page, not an API endpoint.
3. **English only.** Contact: GitHub issues of the public repository `nickburdo/platform-api` (no personal email on the page).
4. **Content** (effective date 2026-11-07): what the service is (portfolio demo: Job Tracker, Health Monitor); what is stored (username, password hash, Google account identifier `sub` for Google sign-in, records the user creates); what is not collected (email, name, photo, contacts; no cookies, ads or analytics); hosting by Cloudflare (processes requests incl. IP addresses; request logs hold method, path, status, timing, request id), link to Cloudflare's privacy policy; no selling or sharing; health data is demo, not medical; deletion via `DELETE /auth/me` (immediate, permanent, with all data); contact via GitHub issues.
5. **No new tests** (user's global rule: tests only on request); the existing gate must stay green.
