# Version 4.3 — Implementation Plan (Glucose in mmol/L)

> Status: **Approved** (2026-11-09, by the user in conversation, including the proposed Decisions 5–9). Execution: inline.
> Depends on: Version 4.2 (`v4.2-plan.md`, deployed 2026-11-08; live cron check 6.6 still pending — independent of this version).

## Goal

Glucose values are in **mmol/L**. Today the unit is not stated anywhere, while the demo data holds mg/dL values (87–132) and the API/OpenAPI examples already use mmol/L (`5.4`). Convert the demo data to mmol/L and state the unit explicitly in the documentation and the OpenAPI document.

## Facts (checked 2026-11-09)

- `health-monitor-db.glucose_measurements` in production: 10 rows, all demo (`user_id IS NULL`), values 87–132. No user rows.
- The unit is not stored, not validated and not documented; validation is only `> 0` (`src/schemas/glucose.schema.ts`).
- mg/dL values appear in `src/db/health-monitor/seed.sql` and `http/glucose.http`; `docs/api.md` and `src/openapi/registry.ts` examples already use `5.4`.

## Decisions

Agreed with the user on 2026-11-09 (items 1–4); items 5–9 are proposed with this plan.

1. **Conversion:** mg/dL → mmol/L by dividing by **18**.
2. **Rounding:** 1 decimal place.
3. **Validation unchanged:** still only `> 0`; no upper bound.
4. **Separate version v4.3**, branch `feat/glucose-mmol`.
5. **Demo values** (seed order): 91→5.1, 128→7.1, 89→4.9, 132→7.3, 87→4.8, 124→6.9, 90→5.0, 130→7.2, 92→5.1, 126→7.0. Written as literals in `seed.sql`, not computed.
6. **Production data is converted in place, without a reseed.** A reseed would reset `demo_refresh_state` and move the v4.2 cron check (6.6) by a day. One-off SQL, demo rows only, idempotent through a guard (values above 30 can only be mg/dL; the highest converted value is 7.3):
   ```sql
   UPDATE glucose_measurements
   SET fasting_value = ROUND(fasting_value / 18.0, 1),
       after_meal_value = ROUND(after_meal_value / 18.0, 1)
   WHERE user_id IS NULL AND COALESCE(fasting_value, after_meal_value) > 30;
   ```
   Not a migration: migrations change schema for every environment, while this is a one-time production data fix (the seed already carries the new values).
7. **Unit in the OpenAPI document:** `description: 'Glucose value in mmol/L'` on `fastingValue` / `afterMealValue` of the `GlucoseMeasurement` response schema, and "Values are in mmol/L." added to the `CreateGlucoseRequest` description; `src/openapi/openapi.json` regenerated with `npm run openapi:generate`. Requires a Worker deploy, because `/openapi.json` and `/docs` are served by the Worker.
8. **`http/glucose.http`:** request values and assertions switched to mmol/L (92→5.1, 128→7.1, 130→7.2, 95→5.3, 90→5.0) for consistency. Pure test data, no behavior change.
9. **No new tests** (user's global rule). Existing schema tests use values like `90` only to check `> 0`; they stay as they are. The gate must stay green.
